# SDDC: Some DLM Design Choices

SDDC is a framework for controlled experiments on diffusion language models (DLMs).
A model is a **recipe** of interchangeable parts: how tokens are represented and
corrupted, what the network predicts and how it is trained, and how it is sampled.
Swap one part, keep the rest fixed, and compare under the same training budget, with
every hyperparameter selected on validation data and the test split used once.

It is the code behind the blog post
[Some design choices in a diffusion language model](https://patrickpynadath1.github.io/blog/diffusion-lm-design-choices).
Each experiment in the post is a [worked example](experiments/README.md) here that you
can rerun.

## What is in it

| Recipe part | Choices |
| --- | --- |
| [Information path](docs/concepts/information-path.md) | token, one-hot, embedding, simplex and spherical representations; masked, uniform, GIDD, Gaussian, Dirichlet, spherical, vMF and blurring corruption; fixed, rank-calibrated and learned (CDCD) noise schedules; multi-view hybrids |
| [Denoising task](docs/concepts/denoising-task.md) | one configurable transformer ([ModularDiT](docs/components/models.md)) and a causal one; posterior, plug-in, score and Gaussian parameterizations; cross-entropy, ELBO-weighted and score objectives |
| [Inference settings](docs/concepts/inference-settings.md) | ancestral, greedy, entropy-bounded, forward-renoising, ODE and composed samplers, at a fixed number of network calls (NFE) |
| [Modifiers](docs/concepts/recipe.md#modifiers-across-the-three-parts) | self-conditioning, block diffusion and encoder-decoder (E2D2), token feedback, insertion/deletion |

More than 25 [paper recipes](docs/guides/paper-recipes.md) are presets: MDLM, SEDD, D3PM,
DUO, GIDD, CDCD, Plaid/RePlaid, CANDI, BD3-LM, E2D2, LLaDA-style, simplex and spherical
flows, autoregressive and others. The tasks are Sudoku, text8, TinyStories (with
byte-level BPE tokenizers from 260 to 10k tokens), N-Queens, mazes, OpenWebText and
TinyGSM. Not every combination is valid; the
[compatibility table](docs/validation/compatibility.md) is generated by building and
running each family with each sampler and modifier.

## Worked examples

| Question from the post | Example | GPU hours |
| --- | --- | --- |
| Is self-conditioning just a deeper network? | [sc-vs-depth](experiments/sc-vs-depth/) | ~110 |
| Does self-conditioning change how the model should be sampled? | [sc-sampler-choice](experiments/sc-sampler-choice/) | none (reads sc-vs-depth's runs) |
| Does the tokenizer change the picture? | [tokenizer-ladder](experiments/tokenizer-ladder/) | ~195 |
| How do learned noise schedules spend training? | [continuous-schedules](experiments/continuous-schedules/) | ~125 |
| Block diffusion: scale the encoder or the decoder? | [block-encoder-decoder](experiments/block-encoder-decoder/) | ~245 |

Each example has its sweep, the exact evaluation splits, the numbers we got
(`expected.csv`), an analysis script that rebuilds the post's tables, and a README with
the protocol and how a rerun can differ. A CPU test runs one tiny case of each end to
end.

## Install

```bash
git clone https://github.com/patrickpynadath1/sddc && cd sddc
uv sync --locked --extra tuning --extra scoring
```

Python 3.10. The lock pins PyTorch for CUDA 12.1 on Linux x86_64, where it also runs on
CPU. On macOS `uv sync --locked` cannot install torch; run GPU work on a server
([remote execution](docs/guides/remote-execution.md)). Sudoku, N-Queens and mazes are
generated on first use; text8 and TinyStories are prepared once with
[`scripts/prepare_data.py`](scripts/prepare_data.py) ([text8](docs/tasks/text8.md),
[TinyStories](docs/tasks/tinystories.md)). The TinyStories BPE tokenizers are in
[`artifacts/tokenizers/`](artifacts/tokenizers/tinystories-bpe/).

Check the install (environment, data caches, tokenizers and a 2-step CPU run):

```bash
uv run --locked --extra tuning --extra scoring python scripts/doctor.py --smoke
```

## Quick start

```bash
# Two training steps of a tiny MDLM on Sudoku, on CPU.
uv run --locked python main.py +experiment=smoke

# Print a recipe's fully composed config without running it.
uv run --locked python main.py +experiment=duo --cfg job

# Train a recipe on a task, then evaluate the checkpoint.
uv run --locked python main.py +experiment=mdlm task=battery/text8
uv run --locked python main.py mode=evaluate evaluation.checkpoint=/path/to/last.ckpt
```

Without overrides, `main.py` trains MDLM on Sudoku-hard on a GPU.

## Running an experiment

An experiment expands recipes x tasks x training seeds into **cases**. Each case
tunes its training choices in an outer Optuna study and each sampler's settings in an
inner one, all on validation; only the winner is scored on the test split. Ray runs the
cases.

```bash
# 1. Expand a sweep into a plan of cases (no training).
uv run --locked --extra tuning --extra scoring python -m core.sweeps.prepare -m \
  +sweep=sc_vs_depth preparation.output=$SDDC_STORAGE_ROOT/plans/sc-vs-depth
uv run --locked --extra tuning --extra scoring python -m core.sweeps.prepare collect $SDDC_STORAGE_ROOT/plans/sc-vs-depth
# 2. Train and tune every case on Ray.
uv run --locked --extra tuning --extra scoring python -m core.sweeps.nested_tuning \
  $SDDC_STORAGE_ROOT/plans/sc-vs-depth/manifest.json \
  --output $SDDC_STORAGE_ROOT/runs/sc-vs-depth --address auto --case-concurrency 4
# 3. Analyze.
uv run --locked --extra scoring python experiments/sc-vs-depth/analyze.py $SDDC_STORAGE_ROOT/runs/sc-vs-depth
```

`SDDC_STORAGE_ROOT` (default `~/.cache/sddc`) holds plans, runs and data caches. W&B
logging is off unless `WANDB_ENTITY` is set (install `--extra tracking`). See
[experiments](docs/guides/experiments.md), [preparing sweeps](docs/guides/programmatic-sweeps.md)
and [nested tuning](docs/guides/nested-tuning.md). To drive a GPU server from a laptop,
see [remote execution](docs/guides/remote-execution.md).

## Layout

| Path | Contents |
| --- | --- |
| `core/` | the library: algorithms, models, processes, schedules, samplers, modifiers, tasks, training, sweeps, analysis, tests |
| `configs/` | Hydra groups under `information_path/`, `denoising_task/`, `inference/`, `modifiers/` and `training/`, recipe presets (`experiment/`) and sweeps (`sweep/`); see [configs/README.md](configs/README.md) |
| `experiments/` | the worked examples |
| `docs/` | concepts, component references, guides; start at [docs/index.md](docs/index.md) |
| `main.py` | train, evaluate or sample (`python -m core.sweeps.frontier` runs pretrained sampling grids) |
| `scripts/` | data preparation, remote execution, the compatibility-table generator |
